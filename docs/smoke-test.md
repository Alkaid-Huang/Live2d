# 冒烟清单

界面与渲染进程在 CI 里跑不了（没有显示器，也不装 GUI 依赖，见 ADR 0002），
所以这两块靠这份清单人工确认。任务切分见 `docs/product.md`。

## 0. 准备

```bat
python -m venv .venv
.venv\Scripts\pip install -e ".[dev,gui]"
copy .env.example .env
```

然后往 `.env` 里填 `LLM_API_KEY`；模型按 `docs/product.md` 的「技术风险」放到
`models/hiyori/`（`LIVE2D_MODEL_PATH` 的默认值就指向这里，写目录或写 json 都认）。

先单独验证渲染这一半，它能把"渲染起不来"和"界面接错了"分开：

```bat
.venv\Scripts\python.exe tests\probe_renderer.py
```

期望输出 `renderer.ready`，会短暂弹出模型窗口。

再单独验证文字与语音那一半（会联网、花 API 额度）：

```bat
.venv\Scripts\python.exe tests\probe_turn.py
```

期望看到逐字回复 + 一行延迟统计 + 音频分片落盘。这两个探针把链路切成两半，
哪一半出问题都不用猜。

## 1. 自动检查（与 CI 同一套）

```bat
.venv\Scripts\ruff check src tests
.venv\Scripts\mypy src
.venv\Scripts\pytest -q --cov --cov-report=term-missing
```

期望三条全过；覆盖率门禁 80% 写在 `pyproject.toml` 里。

## 2. 逐项冒烟

双击 `run.bat` 启动，然后逐项确认。

| # | 检查项 | 怎么做 | 期望 |
|---|---|---|---|
| 1 | 窗口与模型 | 启动 | 出现对话窗口；模型窗口显示角色；状态栏"空闲" |
| 2 | 待机动作 | 盯着看 10 秒 | 角色有呼吸/眨眼，不是一张死图 |
| 3 | 流式文本 | 输入"你好"回车 | 回复逐字出现；状态栏走完"正在回复…"→"合成语音…"→"播放中…"→"空闲" |
| 4 | 口型 | 边听边看嘴 | 说话时嘴跟着音量开合，说完闭上 |
| 5 | 语音 | 同上 | 能听到语音，音色与 `.env` 一致 |
| 6 | 打断（新消息） | 语音还在响时立刻再发一条 | 旧语音立刻停、口型归位；旧回复标"（已打断）"；新回合正常开始 |
| 7 | 打断（停止键） | 回复进行中按"停止" | 同上；输入框里已输入的内容不丢 |
| 8 | 无模型降级 | 把 `LIVE2D_MODEL_PATH` 改成不存在的路径，重启 | 窗口照常、文字与语音照常；界面报"无模型展示"，程序不崩 |
| 9 | 缺 Key 报错 | 清空 `LLM_API_KEY`，重启后发一条 | 状态栏"配置有问题"并写清要改 `.env`，程序不崩 |
| 10 | 换 Provider | 改 `LLM_PROVIDER` / `LLM_MODEL`，重启 | 仍能正常对话（对应 US-4） |
| 11 | 临时音频清理 | 聊几轮后正常关窗 | `tmp_audio/` 变空 |
| 12 | 无残留进程 | 关窗后看任务管理器 | 没有残留的 python 进程 |

## 3. 延迟记录

每次冒烟记一行，攒够样本再算 P95。**口径**：首字 = 按下发送 → 第一个字；
首音 = 按下发送 → 第一片音频就绪；整轮 = 那一回合收尾。这条口径和界面打点、
`product.md` 的 US-1/US-2 一致（为什么首音定 8 秒见 ADR 0003）。

两种取数方式：跑 `run.bat` 看日志，或者跑不加界面的探针：

```bat
.venv\Scripts\python.exe tests\probe_turn.py "用一句话介绍你自己" --turns 3
```

界面日志里每回合会打一行：

```
回合 1a2b3c4d 用时：首字 1200ms / 首音 2600ms / 整轮 4100ms
```

| 日期 | 首字 (ms) | 首音 (ms) | 整轮 (ms) | 备注 |
|---|---|---|---|---|
| 2026-09-21 | 4000 | 7563 | 12984 | 进程冷启动那一轮，含 `import litellm` 的 3.4 秒；分 2 片 |
| 2026-09-21 | 704 | 6907 | 6907 | 稳态；1 片 |
| 2026-09-21 | 1015 | 5187 | 5187 | 稳态；1 片 |
| | | | | |
| | | | | |

上面三行由 `probe_turn --turns 3` 在开发机上打出，经过开发环境的网络（单独量 edge-tts 时
首次调用出现过 16.6 秒的握手开销）。**换到正常桌面用 `run.bat` 复测后请覆盖它们。**
 
## 4. 已知限制（M1 阶段先接受）

- **免费素材看不出情感差异**：官方样例 `Hiyori` 只有 `Idle` 和 `TapBody` 两个动作组，
  也没有表情文件，所以 `stage/cues.py` 对每个情感都会回落到待机动作。
  `docs/product.md` 里 US-3 的"按情感切换 2–3 种表情或动作"**用这份素材验不了**。
  两条出路：换一个带情感动作组的模型，或者加一层"情感 → 面部参数"的直接映射
  （纯函数、可测）。这是 M1 之后要补的第一件事。
- **CI 覆盖不到界面与渲染**：所以两个薄壳（`ui/window.py`、`stage/renderer.py`）
  必须保持薄，逻辑都放在 `ui/state.py` 和 `stage/` 的其他模块里，那些才测得到。
- **音色固定**：edge-tts 只能挑预设音色，不能克隆（见 ADR 0001）。
