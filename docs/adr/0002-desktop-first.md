# 0002. 先做桌面单机多进程，不用 Docker

- 日期：2026-09-15
- 状态：已采纳

## 背景

参照项目 D_sakiko 有两种形态：主体是桌面程序（PyQt5 主进程 + Live2D 渲染子进程 + TTS 子进程，用队列通信），后来才加了 WebUI 形态（FastAPI + WebSocket + 浏览器内 Live2D），两者共用同一套核心代码。

另外，桌面 GUI 和 Docker 天然冲突：容器里跑起来的窗口没法显示给用户。

## 决定

M1 只做桌面形态，单机多进程；不引入 Docker；不在 M1 写任何 HTTP 代码。但把所有核心逻辑放在不依赖界面的层里，为将来的 Web 形态留好接缝。

## 理由

1. **打断和口型在本地最省事。** 取消一个回合只要往队列里放一条命令、停掉播放；换成 HTTP 之后要处理连接取消、任务取消、已经推出去的事件怎么收尾。
2. **音频不需要服务化。** 桌面形态下进程之间传文件路径就够了，不需要音频端点、鉴权、跨设备传输。
3. **Docker 帮不上忙。** 参照项目也没有 Docker，它的一键启动是打包好的程序加一个启动脚本。
4. **先跑通再服务化。** 方向（这条链路的形状）确定之后，形态可以之后换——这正是"小步迭代"的前提。

## 由本决定派生的约束

- **核心层不许 import PyQt5 / pygame / edge_tts。** 这不是洁癖：它同时保证了三件事——单测能跑、CI 不会挂、将来加 Web 不用重写核心。
- 模块之间只传统一事件对象（见 `docs/contracts.md`），业务逻辑不写在界面代码里。
- "一键启动"指的是本机脚本（Windows 下 `run.bat`），不是容器。
- CI 只跑核心层：lint + 类型检查 + 单元测试。界面与渲染只能本地冒烟。

## 代价

- 暂时不能从手机或另一台电脑访问
- CI 覆盖不到界面与渲染，需要人工冒烟清单兜底（M1-6）
- 多进程的退出清理要自己写，Windows 下容易留僵尸进程

## 什么时候转 Web

M1 闭环跑通、桌面形态稳定之后。转的方式：在核心层外面加一层 FastAPI + WebSocket，把事件对象映射成帧，**核心层不动**。映射方式写在 `docs/contracts.md` 第 7 节。
