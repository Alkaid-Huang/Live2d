# 0001. M1 的语音合成先用 edge-tts

- 日期：2026-09-15
- 状态：已采纳

## 背景

语音合成有两条路：

- **edge-tts**：微软在线语音服务的封装。调用简单，零模型加载，不需要 GPU；代价是依赖网络，音色只能从预设里挑，音质一般。
- **本地模型（GPT-SoVITS 之类）**：参照项目走的路。可以克隆出任意角色的音色，离线可用；代价是要下载几 GB 模型，首次出声要等模型加载（可能几十秒），显存吃紧（参照项目 README 写的是 6G 左右）。

## 决定

M1 用 edge-tts，但**把 TTS 做成可替换的后端接口**。换后端只改 `tts/` 内部和 `.env`，上层不动。

## 理由

1. M1 的目标是把链路跑通并让它可测，不是追求音质。edge-tts 让"语音"这一环从第一天就能工作。
2. 求职项目要能在别人的电脑上跑起来。要求面试官有 6G 显存和几 GB 模型下载量，门槛太高。
3. 抽象接口的成本很低（大概一天），换后端时的收益很大，所以先抽象再实现。

## 代价

- **依赖网络**：离线用不了，可能被限流。所以产品描述里不能写"数据不出本机"——文本会发给微软的在线服务。
- **音色固定**：不能克隆成自己的角色。
- **必须提前抽象接口**，否则换的时候要连调用方一起重写。

## 由本决定派生的约束

- 口型**不使用** edge-tts 的逐字时间戳，改用播放音频的音量驱动。时间戳是 edge-tts 独有的，本地模型没有；现在图省事接上，将来就得重写口型。
- edge 专属参数（音色 ID、语速）放在配置的 `TTS_EDGE_` 前缀下，不进通用配置。
- 合成结果统一产出**文件分片**（路径 + 时长 + 格式），不产出音频流。本地模型天然产文件，edge-tts 存成文件只是适配器里的几行。
- 界面从第一天就支持"合成中"状态，不假设合成是瞬间完成的。

## 什么时候换成后端

满足任意两条就换：

- 需要一个专属音色（不用预设音色）
- 需要在无网络环境下演示
- 网络延迟或限流成为实际困扰

换的时候要做：写一个新的 `TtsBackend` 实现 + 新增一条 ADR，**不改 `docs/contracts.md`**。如果发现必须改契约，说明接口抽象做错了，先修接口。
